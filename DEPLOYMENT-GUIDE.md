# VIM Turkey Work Visa — Complete GitHub Pages Deployment Guide

This guide is specific to THIS project and its current file structure. Follow every step in order.

---

## 1. Project Build Requirements

This project uses **Vite + React + TypeScript**. You CANNOT publish the source files directly to GitHub Pages. You MUST build the project first, then deploy the built `dist/` folder.

The build command is:

```bash
npm install
npm run build
```

After building, a `dist/` folder is created containing:

- `index.html`
- `assets/index-XXXXXX.css`
- `assets/index-XXXXXX.js`

These are the only files GitHub Pages needs. The `src/` folder, `node_modules/`, and config files are NOT needed on GitHub Pages.

The project is already configured for GitHub Pages compatibility with `base: './'` in `vite.config.ts`, which means all asset paths are relative and will work under any subpath like `https://visaimmigration-vim.github.io/<repository-name>/`.

### Must NOT include (already in `.gitignore`):

- `node_modules/` — installed via `npm install`
- `dist/` — generated by `npm run build`
- `.env` — contains secrets, never commit
- `.bolt/` — internal config

### About the `dist/` folder:

You have two options:

- **Option A (Recommended):** Push the source code, then use a GitHub Action or manual build to generate `dist/` and deploy it. This keeps the repo clean.
- **Option B (Simpler):** Build locally, then push the `dist/` folder contents to a `gh-pages` branch or to a `docs/` folder. This is the easiest approach for non-developers.

This guide uses **Option B** — build locally and push the `dist/` output.

## 7. Step-by-Step: Deploy the Built Files to GitHub Pages

### Step 7.1 — Build the project (if not already done)

```bash
npm run build
```

### Step 7.2 — Create a gh-pages branch with only the dist contents

Run these commands one by one:

```bash
git checkout -b gh-pages
git rm -r --cached .
```

This removes all tracked files from the staging area without deleting them from disk.

### Step 7.3 — Copy dist contents to the root

You need to copy everything from the `dist/` folder to the repository root so GitHub Pages can serve it. Run:

**On Windows (PowerShell):**

```powershell
Copy-Item -Path dist\* -Destination . -Recurse -Force
```

**On Mac/Linux:**

```bash
cp -r dist/* .
```

### Step 7.4 — Add a .nojekyll file

This prevents GitHub Pages from processing Jekyll, which can break files starting with underscores:

```bash
touch .nojekyll
```

On Windows PowerShell:

```powershell
New-Item .nojekyll -ItemType File
```

### Step 7.5 — Stage and commit only the built files

```bash
git add index.html .nojekyll assets/
git commit -m "Deploy to GitHub Pages"
```

### Step 7.6 — Push the gh-pages branch

```bash
git push origin gh-pages
```

### Step 7.7 — Switch back to main branch

```bash
git checkout main
```

### Step 8.3 — Wait for deployment

GitHub Pages takes 1-5 minutes to build. You will see a green message at the top of the Pages settings with your deployed URL:

```
Your site is live at https://visaimmigration-vim.github.io/vim-turkey-visa/
```

## 9. Final GitHub Pages URL Format

The URL follows this format:

```
https://<your-github-username>.github.io/<your-repository-name>/
```

For example, if your GitHub username is `visaimmigration-vim` and your repository is named `vim-turkey-visa`:

```
https://visaimmigration-vim.github.io/vim-turkey-visa/
```

If you name your repository exactly `visaimmigration-vim.github.io` (your username + `.github.io`), then the URL will be:

```
https://visaimmigration-vim.github.io/
```

This is a special case — GitHub treats `<username>.github.io` repositories as user sites served from the root.

## 11. Common GitHub Pages Errors and Solutions

### Error: Page shows 404

**Cause:** The repository is private, or the gh-pages branch doesn't exist, or Pages is not configured.

**Solution:**
1. Make sure the repository is **Public** (Settings → General → Danger Zone → Change visibility)
2. Make sure the `gh-pages` branch exists and contains `index.html` at the root
3. Make sure Pages source is set to `gh-pages` branch (Settings → Pages)
4. Wait 5 minutes for the first deployment

### Error: Page loads but CSS is missing (unstyled HTML)

**Cause:** The `base` path in Vite is wrong, or assets are in a subfolder.

**Solution:**
1. Check that `vite.config.ts` has `base: './'` — it already does in this project
2. Rebuild with `npm run build` and re-push the `dist/` contents
3. Open the deployed `index.html` and check that the `<link>` and `<script>` tags use relative paths like `./assets/index-XXXXXX.css` (not `/assets/...`)

### Error: Page loads but JavaScript does not work

**Cause:** JS file path is broken, or `.nojekyll` file is missing.

**Solution:**
1. Make sure `.nojekyll` exists in the root of the `gh-pages` branch — this prevents GitHub's Jekyll processor from ignoring files starting with `_`
2. Check the browser console (F12 → Console) for 404 errors on `.js` files
3. Rebuild and redeploy if paths look wrong

### Error: Fonts not loading

**Cause:** Google Fonts is blocked, or network issue.

**Solution:**
1. The project loads fonts from Google Fonts CDN — this requires internet access
2. If your users are in a region where Google Fonts is blocked, consider self-hosting the font files
3. This is not a GitHub Pages issue — it's a network/region issue

### Error: Form submission fails or shows error

**Cause:** The Google Apps Script URL is wrong, the Web App is not deployed, or access is set to "Anyone with Google account" instead of "Anyone".

**Solution:**
1. Verify the URL in `src/config.ts` matches your deployed Apps Script Web App URL exactly
2. Redeploy the Apps Script: Deploy → Manage deployments → Edit → Set "Who has access" to **Anyone** → Deploy
3. If you changed the Apps Script code, create a **new deployment** (not just saving) — old URLs may not update
4. Rebuild the frontend (`npm run build`) and redeploy to GitHub Pages

### Error: Persian text shows as gibberish (Mojibake)

**Cause:** Character encoding issue — the HTML file is not UTF-8.

**Solution:**
1. Make sure `index.html` has `<meta charset="UTF-8" />` in the `<head>` — it already does
2. Make sure your text editor saves files as UTF-8 (VS Code does this by default)
3. Rebuild and redeploy

### Error: Images or icons broken

**Cause:** This project does not use local image files — it uses CSS-based Turkish flag elements and Lucide React icons. If icons are broken, the JS bundle may not be loading.

**Solution:**
1. Check the browser console for JS loading errors
2. Verify the `assets/` folder was pushed to the `gh-pages` branch
3. Rebuild and redeploy

### Error: "Site is building" message for too long

**Cause:** GitHub Pages build queue is slow, or there is a Jekyll processing issue.

**Solution:**
1. Wait up to 10 minutes
2. Make sure `.nojekyll` file exists in the `gh-pages` branch
3. Check Actions tab for any failed deployments

### Error: Changes not showing after update

**Cause:** Browser cache, or the old `gh-pages` branch was not updated.

**Solution:**
1. Hard refresh: Ctrl+Shift+R (Windows) or Cmd+Shift+R (Mac)
2. Rebuild locally: `npm run build`
3. Copy new `dist/` contents to the `gh-pages` branch
4. Commit and push: `git add . && git commit -m "Update deployment" && git push origin gh-pages`
5. Wait 2-5 minutes

## 12. Alternative: Deploy Using a GitHub Action (Automated)

If you prefer automatic deployments on every push to `main`:

### Step 12.1 — Create a workflow file

Create a file at `.github/workflows/deploy.yml` in the `main` branch:

```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]

permissions:
  contents: read
  pages: write
  id-token: write

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm install
      - run: npm run build
      - uses: actions/upload-pages-artifact@v3
        with:
          path: dist
      - uses: actions/deploy-pages@v4
```

### Step 12.2 — Change Pages source

Go to Settings → Pages → Source → select **GitHub Actions** instead of a branch.

### Step 12.3 — Push to main

Every push to `main` will now automatically build and deploy. No manual `dist/` copying needed.
